# DESIGN

Документация по устройству проекта «Быки и коровы»: какие структуры данных и алгоритмы использованы, какова их сложность и какие принципы чистого кода применены.

Обозначения, которые используются во всём документе:

- `L` — длина секретной последовательности (`length`, в приложении 2–6);
- `B` — основание системы счисления (`base`: 2, 8, 10 или 16).

Всегда выполняется `L ≤ B`: секрет состоит из **неповторяющихся** цифр, поэтому длина не может превышать размер алфавита.

## 1. Структуры данных и алгоритмы

### 1.1. Структура кода

```
src/
├── functions/   чистые функции правил игры (без DOM и без состояния)
├── game/        модель состояния: раунд, настройки, рекорды, хранилище
├── ui/          отрисовка экранов (DOM)
├── utilities/   универсальные функции: createEl, createTable, Modal, StorageHelper
└── main.ts      состояние приложения
```

### 1.2. Состояние игры

```ts
type AppState = {
  readonly settings: Settings;
  readonly round: Round | null; // null — экран настроек, Round — идёт или завершена игра
};
```

| Структура                                      | Где                                 | Что хранит                                                      |
| ---------------------------------------------- | ----------------------------------- | --------------------------------------------------------------- |
| `Settings { length, base }`                    | [settings.ts](src/game/settings.ts) | выбранные длину и основание                                     |
| `Round`                                        | [game.ts](src/game/game.ts)         | настройки раунда, секрет, историю попыток, время начала и конца |
| `Attempt { guess, bulls, cows }`               | [game.ts](src/game/game.ts)         | одну оценённую попытку                                          |
| `RecordEntry { attempts, timeMs, finishedAt }` | [records.ts](src/game/records.ts)   | одну запись таблицы рекордов                                    |

**Почему именно так:**

- **История попыток — массив `readonly Attempt[]`.** Попытки — это упорядоченная по времени последовательность, в которую только добавляют в конец. Массив даёт именно это: порядок сохраняется сам, номер попытки — это `index + 1`, количество попыток — `history.length` за `O(1)`, а таблица истории строится одним проходом `map`. `Set` или `Map` порядок для таблицы не дали бы, а дублировали бы данные.
- **Повторный ввод — `history.some(...)`, за `O(n)`.** Здесь `n` — число попыток в раунде. Заводить рядом `Set` строк ради этого не стоит: две структуры пришлось бы синхронизировать, и выигрыш был бы незаметен.
- **Признак завершения — поле `finishedAt: number | null`, а не отдельный `boolean`.** Одно поле сразу отвечает на два вопроса: «закончена ли игра» (`isFinished`) и «сколько она длилась» (`elapsedMs`). Два независимых поля могли бы разойтись (`finished = true`, но `finishedAt = null`); с одним полем такое состояние невозможно.
- **`round: Round | null` вместо флага «на каком мы экране».** Тип сам запрещает обращаться к раунду на экране настроек.
- **`Radix` — объединение литералов `2 | 8 | 10 | 16`**, выведенное из объекта `RADIX` ([constants.ts](src/functions/constants.ts)). Недопустимое основание (скажем, `7`) не пройдёт проверку типов, а список допустимых значений существует в единственном экземпляре.
- **`submitGuess` возвращает ту же ссылку на раунд, если ход отклонён** (игра окончена, ввод некорректен или повтор). Вызывающий код сравнивает `nextRound === round` и по этому понимает, что ход не принят.
- **Рекорды — отсортированный массив длиной не больше `TOP_N = 5`** для каждой пары `(base, length)`; ключ в `localStorage` — `bulls-and-cows:records:<base>:<length>`. Для маленького топа массив + `toSorted(compareRecords).slice(0, limit)` проще и надёжнее, чем куча или дерево. Порядок: меньше попыток лучше, при равенстве — меньше время (`compareRecords`).

### 1.3. Алгоритм `evaluateGuess`

Файл: [src/functions/evaluateGuess.ts](src/functions/evaluateGuess.ts).

**Что делает.** Сравнивает попытку с секретом и возвращает `{ bulls, cows }`:

- **bull** — цифра совпала и по значению, и по позиции;
- **cow** — цифра есть в секрете, но стоит на другой позиции.

**Шаги.**

1. Привести обе строки к нижнему регистру и разбить на массивы символов (`A` и `a` — одна и та же цифра).
2. **Быки.** Один проход по секрету: на каждой позиции `i` сравнить `secret[i]` с `guess[i]`, посчитать совпадения.
3. **Общие цифры.** Для каждой цифры секрета проверить, содержится ли она где-нибудь в попытке (`guessArr.includes`), и посчитать такие цифры.
4. **Коровы = общие цифры − быки.** Каждый бык тоже входит в число общих цифр (она есть в обеих строках), поэтому его нужно вычесть: бык не может быть одновременно коровой.

**Почему алгоритм верен.** Шаг 3 даёт верное число общих цифр, только если цифры внутри каждой строки не повторяются (иначе одна и та же цифра будет посчитана дважды). Это гарантируется снаружи: секрет создаётся `generateSecret` без повторов, а попытка проходит `isValidGuess` (проверка на дубликаты). Поэтому `evaluateGuess` намеренно не повторяет эти проверки — это предусловие функции. При вводе с повторами (`"1123"`) подсчёт коров был бы неверным; в приложении до `evaluateGuess` такой ввод не доходит (`submitGuess` вызывает `isValidGuess` первым).

### 1.4. Алгоритм `countPossibleSecrets`

Файл: [src/functions/countPossibleSecrets.ts](src/functions/countPossibleSecrets.ts). Используется в [settingsScreen.ts](src/ui/settingsScreen.ts) для строки «Possible secrets: …».

**Что считает.** Количество различных секретов длины `L` в системе с основанием `B`, у которых все цифры разные. Это число **размещений** без повторений:

```
A(B, L) = B · (B − 1) · … · (B − L + 1) = B! / (B − L)!
```

Рассуждение: на первую позицию подходит любая из `B` цифр, на вторую — любая из оставшихся `B − 1`, на третью — `B − 2` и так далее. Ведущий ноль разрешён (`"0123"` — допустимый секрет), поэтому первая позиция не ограничена.

**Реализация — рекурсия с мемоизацией:**

```
count(L, B) = 0                         если L > B       (уникальных цифр не хватает)
count(L, B) = 1                         если L = 0       (одна пустая последовательность)
count(L, B) = count(L − 1, B) · (B − L + 1)   иначе
```

Результаты запоминаются в `Map<string, number>` с ключом `"<base>:<length>"`. Мемоизация спрятана в замыкании (`countPossibleSecretsCreator`): кеш приватный и живёт столько же, сколько модуль.

**Примеры.**

| `B` | `L` | Результат                                   |
| --- | --- | ------------------------------------------- |
| 10  | 4   | 10 · 9 · 8 · 7 = **5 040**                  |
| 16  | 6   | 16 · 15 · 14 · 13 · 12 · 11 = **5 765 760** |
| 2   | 2   | 2 · 1 = **2**                               |
| 2   | 3   | **0** (`L > B`)                             |

Переполнения не будет: результат максимум `16!/10! ≈ 5,8·10⁶`, далеко от предела безопасных целых (`2⁵³`).

### 1.5. Остальные алгоритмы кратко

- **`generateSecret`** ([файл](src/functions/generateSecret.ts)) — выборка с отбраковкой: тянет случайную цифру `Math.trunc(random() * base)`, переводит в строку в нужной системе и добавляет в результат, если такой цифры в нём ещё нет. Повторяет, пока длина не достигнет `L`.
- **`isValidGuess`** ([файл](src/functions/isValidGuess.ts)) — три проверки подряд, от дешёвой к дорогой: длина → отсутствие повторов (через `Set`) → каждый символ принадлежит алфавиту системы (`createDigitValidator`).
- **`createDigitValidator`** ([файл](src/functions/createDigitValidator.ts)) — фабрика: один раз вырезает из `DIGITS` первые `B` символов и возвращает предикат «это допустимая цифра».

## 2. Сложность

`L` — длина секрета, `B` — основание. Ограничения приложения: `L ≤ 6`, `B ≤ 16`, поэтому практически всё выполняется за константу. Ниже — оценка «в общем виде», как функции от `L` и `B`, а затем что это значит для реальных размеров.

| Функция                | Время                                                 | Память     |
| ---------------------- | ----------------------------------------------------- | ---------- |
| `generateSecret`       | в среднем `O(L · E)`, см. ниже; `O(L²)` при `L ≤ B/2` | `O(L)`     |
| `evaluateGuess`        | `O(L²)`                                               | `O(L)`     |
| `isValidGuess`         | `O(B + L · B)` = `O(L · B)`                           | `O(L + B)` |
| `countPossibleSecrets` | первый вызов `O(L)`, повторный `O(1)`                 | `O(L)`     |

### `generateSecret` — в среднем `O(L²)` (при `L ≤ B/2`), `O(B² log B)` при `L = B`

Цикл `while` делает попытки, пока не наберёт `L` разных цифр. Одна итерация стоит `O(L)`: `random()`, `trunc` и `toString` — константа, а `result.includes(item)` просматривает строку длиной до `L`.

Сколько итераций? Чтобы выбрать `i`-ю по счёту новую цифру (когда `i` уже взято), нужно «попасть» в одну из `B − i` ещё не использованных цифр из `B`. Вероятность успеха в одной попытке — `(B − i)/B`, значит в среднем нужно `B/(B − i)` попыток. Суммируем по `i = 0 … L−1`:

```
E = Σ B / (B − i)  при i от 0 до L−1
```

- Пока `L ≤ B/2`, каждое слагаемое не больше 2, так что `E ≤ 2L = O(L)`. Тогда общее время `O(E · L) = O(L²)`.
- В худшем допустимом случае `L = B` последняя цифра требует в среднем `B` попыток, и сумма — это `B · H_B ≈ B · ln B` (гармоническое число). Тогда время `O(B² log B)`.

Важное замечание: это **математическое ожидание**, а не гарантия. Верхней границы числа итераций нет: при неудачной последовательности `random()` цикл может длиться дольше. С вероятностью 1 он завершается, и на практике (`B ≤ 16`) ожидается не более нескольких десятков итераций. Память `O(L)` — только строка-результат.

Почему не перемешивание Фишера–Йейтса, которое даёт `O(B)` детерминированно? Для `L ≤ 6` и `B ≤ 16` разницы не видно, а отбраковка короче и читается с первого раза. Если бы `B` вырос до тысяч, стоило бы перейти на частичный Фишер–Йейтс.

### `evaluateGuess` — `O(L²)`

- `toLowerCase` и `split("")` для обеих строк — `O(L)`.
- Подсчёт быков — один `reduce` по `L` позициям, на каждой сравнение за `O(1)` → `O(L)`.
- Подсчёт общих цифр — `reduce` по `L` цифрам секрета, и на каждой `guessArr.includes(cur)` — линейный поиск по `L` элементам → `L · L = O(L²)`.

Доминирует вторая часть: итого `O(L²)`. Память `O(L)` на два массива символов.

Можно ли быстрее? Да: положить цифры попытки в `Set` и проверять принадлежность за `O(1)`, получив `O(L)`. Но при `L ≤ 6` это 36 сравнений максимум, а накладные расходы на создание `Set` сравнимы с самим поиском; код с `includes` проще. Это осознанный компромисс: сложность растёт квадратично, но `L` ограничено сверху.

### `isValidGuess` — `O(L · B)`, на практике `O(L)`

1. `guess.length !== length` — `O(1)`, и при несовпадении функция сразу выходит.
2. `toLowerCase` + `split` — `O(L)`.
3. `new Set(guessArr)` — `O(L)` (вставка в хеш-таблицу за `O(1)` в среднем) и сравнение размеров — повторы отсеяны.
4. `createDigitValidator(base)` — один раз `DIGITS.slice(0, base)`, `O(B)`.
5. `every(...)` — для каждого из `L` символов `allowed.includes(...)` по строке длиной `B` → `O(L · B)`.

Итого `O(1 + L + L + B + L·B) = O(L · B)`. Поскольку `B ≤ 16` — константа, на практике `O(L)`. Дешёвые проверки стоят первыми, чтобы заведомо неверный ввод отбрасывался как можно раньше.

### `countPossibleSecrets` — `O(L)` при первом вызове, `O(1)` при повторном

- **Первый вызов** для пары `(L, B)` спускается по рекурсии `L, L−1, …, 1, 0` (глубина `L`), на каждом уровне делает одно умножение и одну запись в `Map` → `O(L)` по времени, `O(L)` по памяти (стек вызовов + записи кеша).
- **Повторный вызов** с теми же параметрами — один поиск в `Map` по короткой строке-ключу → `O(1)`.
- Благодаря мемоизации кеш работает и «внутри» рекурсии: вызов `(10, 6)` заполняет записи для `(10, 1) … (10, 6)`, так что вызов `(10, 4)` потом — тоже `O(1)`.

Размер кеша ограничен числом различных пар `(B, k)`: при допустимых настройках (длины до 6, `k ≤ B`) это не больше 20 записей.

## 3. Принципы чистого кода

Ниже — принципы и конкретные места, где они применены.

### 3.1. Говорящие имена

Имена передают смысл, поэтому комментарии почти не нужны.

- Предикаты начинаются с `is` / `has`: `isValidGuess` ([isValidGuess.ts](src/functions/isValidGuess.ts)), `isFinished`, `hasAttempt` ([game.ts](src/game/game.ts)), `isRadix`, `isRecordList` / `isRecordEntry` ([records.ts](src/game/records.ts)).
- Названия с единицами измерения и ролью: `elapsedMs`, `timeMs`, `startedAt`, `finishedAt` — сразу видно, что это миллисекунды и моменты времени.
- Функции-фабрики называются глаголом `create…`: `createDigitValidator`, `createEl`, `createTable`, `createModal`.
- Переменные в `evaluateGuess` — `secretArr`, `guessArr`, `bulls`, `cows`: они совпадают с терминами предметной области.

### 3.2. Функции маленькие и выполняют одну задачу

- Весь [game.ts](src/game/game.ts) состоит из коротких функций по 1–15 строк: `startRound`, `isFinished`, `hasAttempt`, `submitGuess`, `elapsedMs`, `toRecord`. Каждая отвечает на один вопрос.
- [settings.ts](src/game/settings.ts): `maxLength`, `availableLengths`, `changeBase`, `changeLength` — по одной задаче.

### 3.3. Разделение ответственности (Single Responsibility)

Каждый слой занимается одним делом (см. структуру в п. 1.1):

- [src/functions/](src/functions) — правила игры, никакого DOM;
- [src/game/](src/game) — состояние и его преобразования;
- [src/ui/](src/ui) — только отрисовка и подписка на события;
- [src/main.ts](src/main.ts) — единственное место, где состояние изменяется (`setState`), и перерисовка (`render`).

Даже внутри `game/` хранилище отделено от логики: чистая логика рекордов (`addRecord`, `compareRecords`) лежит в [records.ts](src/game/records.ts), а работа с `localStorage` — в [recordsStorage.ts](src/game/recordsStorage.ts), и она, в свою очередь, не работает с хранилищем напрямую, а идёт через обёртку [StorageHelper.ts](src/utilities/StorageHelper.ts).

### 3.4. Зависимости передаются параметрами

Время приходит в логику раунда аргументом: `startRound(settings, secret, startedAt)`, `submitGuess(round, rawGuess, now)`, `elapsedMs(round, now)` ([game.ts](src/game/game.ts)). Внутри `game.ts` нет ни одного вызова `Date.now()` — его делает вызывающий код в [main.ts](src/main.ts), поэтому логика раунда детерминирована и проверяется без подмены часов.

### 3.5. Ранний выход (guard clauses) вместо вложенных `if`

- `generateSecret` проверяет `length < 1` и `length > base` и бросает `RangeError` до основной работы.
- `countPossibles` ([countPossibleSecrets.ts](src/functions/countPossibleSecrets.ts)) начинается с базовых случаев `length > base` и `length === 0`.
- `submitGuess` отсекает завершённую игру, неверный ввод и повтор одним условием с возвратом.
- `handleGuess` в [main.ts](src/main.ts) выходит сразу, если раунда нет или ход не принят.

Основной сценарий в каждой из этих функций идёт на одном уровне вложенности, без «лесенки».

### 3.6. DRY — без дублирования

- Одна функция `createTable` ([createTable.ts](src/utilities/createTable.ts)) строит и таблицу истории попыток в [gameScreen.ts](src/ui/gameScreen.ts), и таблицу рекордов в [recordsTable.ts](src/ui/recordsTable.ts).
- `createEl` ([createEl.ts](src/utilities/createEl.ts)) — единственный способ создавать элементы во всём `ui/` и в `Modal.ts`: нет ни одного повтора `document.createElement` + `setAttribute` + `append`.
- `formatSeconds` ([format.ts](src/ui/format.ts)) используется и в таблице рекордов, и в статусе игры.
- Алфавит цифр определён один раз — `DIGITS` и `RADIX` в [constants.ts](src/functions/constants.ts); из него выведены тип `Radix`, валидатор цифр, `RADIX_OPTIONS`, `baseName`.

### 3.7. Никаких «магических» чисел и строк

Именованные константы вместо литералов в коде: `TOP_N` ([records.ts](src/game/records.ts)), `MIN_LENGTH`, `MAX_LENGTH`, `DEFAULT_SETTINGS` ([settings.ts](src/game/settings.ts)), `RADIX`, `DIGITS` ([constants.ts](src/functions/constants.ts)). Ключ хранилища собирается в одном месте — `storageKey` ([recordsStorage.ts](src/game/recordsStorage.ts)).

### 3.8. Явная обработка ошибок

- `generateSecret` выбрасывает `RangeError` с понятным сообщением при недопустимых аргументах.
- Данные из `localStorage` не заслуживают доверия: `loadRecords` ([recordsStorage.ts](src/game/recordsStorage.ts)) проверяет прочитанное типовым предикатом `isRecordList` и при любой ошибке или несоответствии формату возвращает пустой список. Повреждённое хранилище не ломает игру.
- `StorageHelper` ([StorageHelper.ts](src/utilities/StorageHelper.ts)) превращает разные сбои (нет данных, невалидный JSON, переполнение квоты) в ошибки с понятным текстом и ключом.
- `saveRecords` перехватывает ошибку записи и логирует её через `console.error`: потеря рекорда не должна обрушить игру.
